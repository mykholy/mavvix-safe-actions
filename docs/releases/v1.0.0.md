# Mavvix Safe Actions v1.0.0

First stable SemVer release of the **opt-in, fail-closed bounded bulk-action API for Filament 5**.

## Features

- Server-trusted actor / panel / tenant / action preflight context with expiring, one-use tickets.
- Verified filtered/current-page/all-matching selections, default upper bound of 500 selected records.
- Scope, permissions, model values and selectable rows checked again at confirmation.
- Synchronous, single-connection Eloquent transactions with selected-row locks and same-transaction ticket consumption.
- Safe declarative scalar update summary and built-in identifier/ownership/timestamp restrictions.
- Native Filament confirmation modal, English/Arabic messages, prune command and translation/config publishing.
- MySQL 8.4 and PostgreSQL 16 two-process and multi-worker regression evidence; Laravel 12/PHP 8.2–8.3 and Laravel 13/PHP 8.4 test coverage.

## Compatibility / install

Requires PHP ^8.2, Filament ^5.0, Laravel ^12.0 or ^13.0. Requires a supported Eloquent table with a single-column key; excludes JOIN, GROUP BY, HAVING, DISTINCT, UNION, pivot identity, duplicate relationship rows, non-Eloquent sources and cross-database transactions.

When indexed on Packagist:

```bash
composer require mykholy/mavvix-safe-actions:^1.0
php artisan vendor:publish --tag=safe-actions-migrations
php artisan migrate
```

Until Packagist indexing, install exact tag from a project-specific Composer VCS repository:

```bash
composer config repositories.mavvix vcs https://github.com/mykholy/mavvix-safe-actions
composer require "mykholy/mavvix-safe-actions:^1.0"
php artisan vendor:publish --tag=safe-actions-migrations
php artisan migrate
```

See README for the action configuration and required trusted scope, guard, policy and server-side tenant handling.

## Security and accessibility disclosure

The release includes a documented [first-party, automated source/security review](../security-review-v1.0.0.md) and green CI. **It has NOT received independent security sign-off, a human screen-reader audit, or full production-like load qualification.** Use in production only after assessing your application-specific policies, tenants, observers, model side effects and operational constraints.

Only mutations on one database connection may roll back. External APIs, queues, email, storage, cross-database updates and arbitrary model observers are **not** protected. Unsupported selections fail closed.

Report suspected vulnerabilities privately following SECURITY.md. The release is MIT licensed and supplied without performance or security certification.
